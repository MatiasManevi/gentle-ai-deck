02 · Ecosystem Overview

Engineering AI workflows

Instead of "ask and pray," we structure the work on an assembly line of experts. Spec-Driven Development applies software engineering principles to the AI workflow.

03 · SDD Orchestrator

Specialized roles

Explorer (reads code), Proposer (defines what), Spec Writer (requirements), Designer (architecture), Task Planner (splits work), Implementer (writes code), Verifier (validates quality).

04 · SDD Orchestrator

Real example: creating users endpoint

/sdd:new → Explorer detects stack → Proposer defines scope → Spec + Design run in paralell → Tasks divides the design in 4 tasks → Implementer generates code → Verifier validates against specs.

05 · Engram

Compaction kills decisions

You work 2 hours defining architecture. The system compacts. The agent no longer remembers you decided to use Clean Architecture with DI. It generates generic code.

06 · Engram

Engram: save signals, not everything

Engram does not save everything (that's noise). It save signals: decisions, resolved errors, patterns. Structured observations with What/Why/Where/Learned.

07 · Engram

The Engram Loop: two sessions

Session 1: design → mem_save. Session 2: implement → mem_search retrieves decision → consistent code. Without Engram session 2 ignores session 1. With Engram there's real continuity.

08 · Engram

Git or Cloud

Two valid sync paths, both work for solo and team. Git sync uses your existing repo, no extra infra, async (commit-based).

Engram Cloud is a self-hosted server with web dashboard, real-time autosync, multi-user with roles. You choose based on your need: simplicity or visibility.
