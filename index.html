02 · SDD Orchestrator

Sub-agents: the assembly line of experts

Instead of "ask and pray," we structure the work on an assembly line of experts. The orchestrator delegates each phase to an ephemeral sub-agent with fresh context. It spawns, executes, reports, and dies.

Skills resolve WHAT context to load, but a single agent still accumulates noise. The orchestrator delegates each task to a specialized sub-agent that receives only what it needs. Maximum precision, zero accumulated noise.

03 · SDD Orchestrator

Specialized roles

Explorer (reads code), Proposer (defines what), Spec Writer (requirements), Designer (architecture), Task Planner (splits work), Implementer (writes code), Verifier (validates quality).

04 · SDD Orchestrator

Real example: creating users endpoint

/sdd:new → Explorer detects stack → Proposer defines scope → Spec + Design run in paralell → Tasks divides the design in 4 tasks → Implementer generates code → Verifier validates against specs.

06 · Engram

Engram: save signals, not everything

Engram does not save everything (that's noise). It save signals: decisions, resolved errors, patterns. Structured observations with What/Why/Where/Learned.

07 · Engram

The Engram Loop: two sessions

Session 1: design → mem_save. Session 2: implement → mem_search retrieves decision → consistent code. Without Engram session 2 ignores session 1. With Engram there's real continuity.

08 · Engram

Synchronized knowledge across the team

Two valid sync paths, both work for solo and team. Git sync uses your existing repo, no extra infra, async (commit-based).

Engram Cloud is a self-hosted server with web dashboard, real-time autosync, multi-user with roles. You choose based on your need: simplicity or visibility.

09 · Skills

Why Skills?

A single AGENTS.md grows linearly with the project, consuming more tokens and increasing hallucination risk with each new convention. Skills decompose that monolith into atomic, load-on-demand modules that keep the context window lean and the output consistent.

Instead of one bloated file, each skill declares its own conventions. The agent only loads what matches the current task — no wasted tokens, no conflicting instructions.

10 · Skills

Trigger-based lazy loading

Every skill declares its own trigger conditions — file patterns (e.g., *.go), task keywords (e.g., "spec"), or context signals. When the agent's task matches a trigger, the skill is loaded into context — nothing more.

This is lazy loading applied to LLM instructions. The agent never sees irrelevant skills. The result: a dramatically smaller effective context window, fewer distractions, and no conflicting conventions between unrelated domains.

11 · Skills

Ecosystem Curated Skills

Gentle AI ships with 21 curated skills organized in three categories. SDD Workflow skills drive the full spec-driven lifecycle. Code Quality skills enforce standards and automate reviews. Knowledge skills capture documentation, project management, and collaboration patterns.

Each skill is a self-contained module with its own triggers, conventions, and instructions. They combine like LEGO blocks — use what you need, ignore the rest. Custom skills are just markdown files with frontmatter.
